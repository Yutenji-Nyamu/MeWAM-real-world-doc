# RGB-D、轨迹、mask 与标定：对应到现有 UR5e

更新：2026-09-29。基础设施只读核对版本：[UR5e-RoboTwin-Real，097922c](https://github.com/Yutenji-Nyamu/UR5e-RoboTwin-Real/tree/097922c90bcbfeb1a70c2ecaedbeb16b3fe49235)。本文说明数据准备的工作量；待实现项列入计划。

## 本轮简答：为什么提到这些参数

目的是让 RGB 里的一个点配上正确的深度，再从前后帧得到这个点的 UVD 运动标签。**固定主相机、SDK 对齐 RGB-D、图像坐标中的 UVD** 是当前省工作量的路线。

- **内参**：像素与三维位置之间的换算尺子，程序从相机读取；用于需要三维换算的处理步骤。
- **RGB 与 depth 的内部关系**：彩色与深度镜头略有位置差，SDK 据此把两张图对齐，保证同一像素指同一处物体。
- **相机与机械臂的外参／手眼**：回答“相机看到的位置，换到机器人坐标是多少”。显式世界坐标、机器人模型投影、多视角三维融合等步骤会用到它。

前两项由设备参数和 SDK 处理。固定主相机的像素光流加对应深度差，可以直接构造 UVD；人工手眼测量属于后续引入机器人坐标几何时的工作。机器人动作与相机图像的关系由配对示范学习。

与论文的关系是**几何训练数据怎样产生、部署时采用什么观察**。论文附录简述所采用的采集方式；参数读取、对齐与脚本放在实现记录。仿真中的相机参数由渲染器提供。

已再次核对 [RealSense 官方说明](https://github.com/realsenseai/librealsense/wiki/Projection-in-RealSense-SDK-2.0) 的内参读取、设备内外参、深度单位与帧对齐。现有采集代码的深度保存扩展见下文第 2 节。

## 1. 先回答“目前硬件够不够”

**现有 UR5e 和深度相机可以支撑这条采集路线；主要增量是记录深度、对齐与时间信息，以及离线数据处理。** 目前仓库的相机代码只开启彩色流，因此“设备是深度相机”和“数据已经保存深度”是两件事。

建议先使用固定主相机的 RGB-D 做 Track，腕部相机保存 RGB。这样与固定相机 UVD 预处理最接近，手眼标定可以按后续世界坐标需求再安排。

## 3. “RGB + 深度够吗”

视觉几何部分的核心原料是**同步且对齐的 RGB-D 视频**。策略学习还需要机器人状态、动作目标、夹爪、任务指令及 episode 时间对应；现有仓库已经提供其中多数内容。

| 层级 | 建议保留的内容 | 来源 |
|---|---|---|
| 采集原始数据 | 两视角 RGB、主视角原始 depth／RGB 对齐 depth、时间戳和帧号 | 相机 SDK |
| 相机元数据 | 分辨率、出厂内参、深度尺度、对齐规则；保留原始流时保存内部 RGB↔depth 外参 | 相机 SDK 直接读取 |
| 机器人原始数据 | 关节／TCP 状态、夹爪指令、各自时间戳；自主执行时记录下发 action | RTDE 与控制程序 |
| Episode 元数据 | task／instruction、结果、场景条件 ID、物体／桌布／干扰物 ID | 采集程序与实验记录 |
| 离线派生 | 前景 mask、机器人／物体角色、二维光流、UVD、有效区和置信度 | 规则或 CV 模型 |

对于当前项目的完整 Track 路径，推理端还要提供当前主视角的 depth 和前景 mask。未来 Track 来自模型预测；RAFT 等离线工具用于生成训练监督。若 mask 用复杂模型在线生成，其耗时要计入端到端部署延迟。

## 4. UVD 是什么：只需抓住一个点

一个点在画面中的位置是 `(u,v)`，相机量到的深度是 `d`。点随时间移动，就有 `(Δu,Δv,Δd)`。把点的运动随时间连起来，就是这里使用的 4D 信息。

当前项目编码相隔四帧的局部位移：`(Δu/W, Δv/W, Δd)`，前两项都除图像宽度，深度差使用米。固定相机、对齐深度下可直观写成：

```text
(u2,v2) = (u1,v1) + RGB optical flow
Δd = depth_next(u2,v2) - depth_current(u1,v1)
```

RAFT 用前后两张 RGB 估计像素运动；深度提供第三个分量。有效区域、遮挡、深度空洞和前后向一致性由预处理过滤。若涉及三维重投影或相机运动补偿，再使用相机参数。

“四相位”指帧对分组：`0→4→8…`、`1→5→9…`、`2→6→10…`、`3→7→11…`。它覆盖不同视频起始帧，它描述视频采样的时间起点。

## 5. mask 和角色标签通常怎么来

Mask 是一张黑白图，表示“哪些像素属于关心的前景”。角色标签进一步分为背景、机器人、物体。可从简单路线开始，再按场景复杂程度升级：

| 路线 | 做法 | 适合什么情况 |
|---|---|---|
| 固定 ROI + 深度规则 | 限制桌面工作区，去掉远处背景，拟合或估计桌面高度，再筛选有效深度 | 固定相机、背景简单、道具位置范围明确 |
| 人工框／点提示 + 分割模型 | 对目标物体、机械臂指定区域，使用 SAM 系列分割并在视频中传播 | 外观变化、遮挡、多物体，规则较难稳定 |
| 规则与模型结合 | 分割给候选区域，深度／ROI 筛掉异常像素，少量人工检查 | 本项目较实用的折中 |
| 机器人几何投影 | 用关节状态、URDF 和相机到机器人变换生成机器人区域 | 已有可靠相机外参、需要自动精确角色标签 |

深度阈值可以产生粗前景；“机器人／目标物体／干扰物”语义通常还需要实例提示、跟踪或模型。抽屉、盒子、插接孔这类**静止但与任务有关**的结构也要保留。图像里的低运动区域与不重要区域是两回事。

会用到的公开模块可包括 [RAFT](https://github.com/princeton-vl/RAFT) 和 [SAM 2](https://github.com/facebookresearch/sam2)，相应依赖与预训练权重一般需准备一次。任务规则属于我们自己的小脚本；优先用少量片段检查 mask、角色和 UVD 是否稳定，再决定是否增加模型。

## 6. 标定分三层，工作量差别很大

| 参数 | 通俗含义 | 怎么取得 | 本项目用途 |
|---|---|---|---|
| 内参 K | 像素和相机三维坐标之间的尺子 | RealSense 出厂参数，SDK `get_intrinsics()` | 反投影、几何预处理；按实际分辨率保存 |
| 相机内部 RGB↔depth 外参 | 一个设备里的彩色镜头与深度镜头相对位置 | SDK `get_extrinsics_to()`；`rs.align` 使用它 | 把深度对齐到 RGB |
| 相机↔机器人／世界外参、手眼 | 相机相对于机器人／末端的位置与朝向 | 棋盘格／标定板等测量，或已有可靠标定记录 | 世界点云融合、URDF 投影、移动腕相机运动补偿 |

前两层通常直接从设备读取，操作上不用手动拍棋盘格。第三层才是你担心的手工标定工作。

**当前最低工作量路线：固定主相机 + SDK 对齐 RGB-D + 相机坐标里的 UVD。** 先沿用固定相机假设，机器人动作继续用已有机器人基座坐标表示；通过配对示范学习视觉到动作的关系。若后续要把几何显式转到机器人基座、融合多相机点云，或扣除腕相机自身运动，再加对应外参。

使用腕部相机计算图像流时，画面变化同时包含机器人带动相机的运动和物体运动。固定主相机降低这项处理复杂度。拍摄过程中移动固定相机后，应另记相机配置或重新采集一致数据。

官方原理说明：[RealSense Projection](https://github.com/realsenseai/librealsense/wiki/Projection-in-RealSense-SDK-2.0)。原始 Z16 深度乘 `get_depth_scale()` 得到米；零值表示无效深度。裁剪／缩放 RGB 和 depth 时，两者使用同一几何变换，内参同步更新。

## 7. 仿真“也有标定吗”

仿真同样有相机内参和位姿，只是由场景／渲染器精确给出。真实世界通过出厂参数或测量得到，仿真直接从配置读取。仿真里的相机参数是现成的几何真值来源。

## 8. 旧 RGB 数据、伪深度和部署

已有 RGB 可以离线通过 DA3／视频深度模型补伪深度，用 RAFT 补光流，用分割模型补 mask。WAM4D 就使用几何教师产生的深度监督。伪深度需要检查尺度、跨帧一致性和遮挡处误差；硬件实测深度则需检查空洞、反光及 RGB 对齐。

对应的物理相机和分辨率仍一致时，出厂内参可从设备补读；已有 episode 的实际曝光时间、丢帧和同步误差则以原始记录为依据。现在增加保存字段，后续处理更直接。

如果当前模型把 depth／mask 作为在线条件，RGB-only 部署就需要增加在线估计器，或另行训练与验证 RGB-only 路径。视频／深度的未来预测仍需要当前条件与训练目标配合。

## 9. 训练视频专家与做视频展示

实机执行录像直接记录策略表现。若展示“模型预测的视频”，还要确认视频专家是否适配这些真机场景，以及采用什么生成配置。Fast-WAM 展示训练阶段视频共同学习、执行阶段快速动作生成的选择；当前 Metis 方案同时涉及 Video、Track、Action 分支，训练范围在实施时逐项记录。可优先完成策略数据与执行评估，再补预测 RGB／Track 的对应展示。
